| D014 | 2026-10-30 | save-integrity S3a | The workstation keeps immutable `save_snapshots` plus `current_pointers`. `saves` remains the legacy mirror and is not deleted. Bytes already stored are not rewritten. `PUT /saves/{game_id}` from an installed client appends an archived copy and must not move a pointer because the timestamp is newer. The first legacy row, when no pointer exists, still becomes the active save. `POST /saves/{game_id}/snapshots` is idempotent on the client key and on `(game, lineage, sha256)`. A repeated key with different bytes conflicts and writes nothing. `POST /saves/{game_id}/pointer` is compare-and-swap: the snapshot must already be `accepted`, the lineage must match, and `expected_version` must match.
