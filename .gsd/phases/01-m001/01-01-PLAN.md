# S01: Game Registry and Launcher

**Milestone:** M001
**Slice:** S01

**Goal:** Deliver GameRegistry (enumeration + validation of asset definitions), minimal Room persistence for GameInstance metadata, a Material 3 launcher UI, and navigation wiring from launcher to play surface. After this slice: Launcher shows registered games with resume/launch; invalid definitions rejected; last-played ordering deterministic.
**Demo:** Launcher shows registered games with resume/launch; invalid definitions rejected; last-played ordering deterministic

## Must-Haves

- Both known game definitions load through GameRegistry; invalid definitions are rejected; Launcher renders the registry as Material 3 cards; last-played ordering is deterministic; launch/resume selects the intended game instance; ./gradlew :app:assembleDebug --no-daemon passes

## Proof Level

- This slice proves: contract

## Integration Closure

Produces GameRegistry, GameInstance entity + DAO, HubDatabase, LauncherScreen, and HubNavigation for S02/S03/S04 consumption. Preserves route contract play_surface/{gameId} for S02 swap-in.

## Verification

- GameRegistry logs validation results; LauncherScreen logs card render count; HubNavigation logs navigation events

  3. Create `GameInstanceDao` at `app/src/main/java/com/example/hub/database/GameInstanceDao.kt` with: `getAllOrdered()` returning Flow for last-played ordering, `get(gameId)` suspend, `upsert()` suspend, `delete(gameId)` suspend.
  4. Create `HubDatabase` at `app/src/main/java/com/example/hub/database/HubDatabase.kt` as a Room singleton with `gameInstanceDao()` abstract method.

- [x] **T02**: GameRegistry: Enumerate, Validate, and Resolve Game Definitions _(35m)_
  **Why:** R001 requires enumerating registered game definitions from assets/games/, validating with GameDefinitionValidator, rejecting invalid definitions explicitly, and providing deterministic ordering/lookup with metadata for launcher rendering. This is the highest-risk task because it touches the Android asset pipeline for the first time.

  **Do:**
  1. Create `RegisteredGame` data class at `app/src/main/java/com/example/hub/games/RegisteredGame.kt` with fields: `gameId`, `displayName`, `launchUrl`, `adapterId`, `displayDefaults` (nested data class or existing pattern), `lastPlayedAtMillis` (nullable, from DAO).
  2. Create `GameRegistry` at `app/src/main/java/com/example/hub/games/GameRegistry.kt` as a plain class taking `Context`. It reads `assets/games/*.json`, validates each with `GameDefinitionValidator`, caches the validated list, and exposes:
     - `getGames(): List<RegisteredGame>` — ordered deterministically (alphabetical by gameId for cold start; DAO last-played ordering when data exists)
     - `getGame(gameId: String): RegisteredGame?`
     - `allDefinitions: List<DefinitionWithStatus>` — for error reporting
  3. Create `GameRegistryTest` at `app/src/test/java/com/example/hub/games/GameRegistryTest.kt` using classpath resources (same pattern as `GameDefinitionValidatorTest`). Test: both known definitions resolve; invalid JSON rejected; deterministic ordering.
  4. Wire `GameRegistry` to consume `GameInstance` DAO for last-played ordering (depends on Task 1's HubDatabase).

  **Done when:** Both known game definitions load; invalid definitions are rejected; deterministic ordering is verified by test; unit tests pass.
  - Files: `app/src/main/java/com/example/hub/games/RegisteredGame.kt`, `app/src/main/java/com/example/hub/games/GameRegistry.kt`, `app/src/test/java/com/example/hub/games/GameRegistryTest.kt`
  - Verify: ./gradlew :app:testDebugUnitTest --tests "com.example.hub.games.GameRegistryTest" --no-daemon && ./gradlew :app:testDebugUnitTest --tests "com.example.hub.games.GameDefinitionValidatorTest" --no-daemon
- [x] **T03**: LauncherScreen: Material 3 Card UI _(30m)_
  **Why:** R003 requires a Material 3 launcher showing registered games as native cards with recently-played-first ordering, honest availability/status labels, and Resume/Launch actions. The launcher is the normal application entry surface per R004.

  **Do:**
  1. Create `LauncherScreen` composable at `app/src/main/java/com/example/hub/ui/LauncherScreen.kt` using `Scaffold` + `LazyColumn` of `Card` items.
  2. Each card shows: `displayName`, status label (Resume available / Launch), action buttons (Resume where resumable, Launch/start otherwise).
  3. Use `displayDefaults` from `RegisteredGame` for color hints (colorPrimary from game definition).
  4. Order games: games with `lastPlayedAtMillis` first (sorted DESC), then alphabetical by gameId.
  5. Read `GameRegistry` via `remember` + `produceState` (no ViewModel per S01 constraint).
  6. Expose `onLaunch(gameId: String)` and `onResume(gameId: String)` callbacks.

  **Done when:** Launcher renders both games as cards; cards show correct displayName and status; last-played ordering is visually deterministic; build passes.
  - Files: `app/src/main/java/com/example/hub/ui/LauncherScreen.kt`
  - Verify: ./gradlew :app:assembleDebug --no-daemon
