# S02: Play Surface and Native Menu

**Milestone:** M001
**Slice:** S02

**Goal:** Deliver the playable WebView surface and native in-session menu. Four deliverables: (1) SessionState sealed class with nine states and transition validation, (2) WebViewHost composable with stable AndroidView identity across recomposition, (3) NativeMenu composable with seven actions and deterministic Back behavior, (4) Fold-aware layout adapters for cutout/hinge/IME handling. Game remains active while menu opens/closes; WebView identity stable across recomposition and layout changes.
**Demo:** Game remains active while menu opens/closes; WebView identity stable across recomposition and layout changes

## Must-Haves

- SessionState sealed class has nine states and canTransition validates all 81 pairs deterministically
- WebViewHost uses AndroidView with remember(key=gameId) so factory is called once per unique game; profile bound before navigation
- NativeMenu renders seven action items with 48dp touch targets; Android Back closes menu not session
- FoldAwareLayout applies WindowInsets for status bar, nav bar, IME, and display cutout
- PlaySurface composes WebViewHost + NativeMenu + FoldAwareLayout; HubNavigation wires real PlaySurface
- ./gradlew :app:assembleDebug --no-daemon passes; existing tests not regressed

## Proof Level

- This slice proves: high

## Integration Closure

S02 produces SessionState, WebViewHost, NativeMenu, and FoldAwareLayout that S03 consumes as the state machine and UI surface. S02 wires PlaySurface into HubNavigation so the launcher can reach a real WebView. Cross-slice integration point: S03 receives SessionState + WebViewHost as the foundation for SessionController.
