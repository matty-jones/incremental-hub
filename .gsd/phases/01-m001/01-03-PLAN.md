# S03: SessionController Core

**Milestone:** M001
**Slice:** S03

**Goal:** Deliver SessionController as the sole lifecycle owner, BridgeValidator/BridgeHost for origin-restricted message validation, and wire PlaySurface + WebViewHost to controller-driven state. Three deliverables: (1) SessionController lifecycle component with nine-state state machine and validated transitions, (2) BridgeValidator pure validation + BridgeHost WebMessageListener wrapper, (3) PlaySurface wiring replacing local remember state with SessionController observation.
**Demo:** Session transitions unit tested; illegal transitions fail deterministically; stale bridge responses rejected

## Must-Haves

- SessionController exposes StateFlow state with validated transitions; illegal transitions log warning and remain in current state. BridgeValidator rejects origin-mismatch, stale-epoch, and uncorrelated-request messages deterministically on JVM. PlaySurface observes SessionController.state via collectAsState; menu callbacks route through controller. AssembleDebug passes. All S01/S02 tests preserved. New unit tests: SessionControllerTest (≥15), BridgeValidatorTest (≥10).

## Proof Level

- This slice proves: strong

## Integration Closure

S03 produces SessionController consumed by S04. S03 consumes SessionState (S02), WebViewHost (S02), NativeMenu (S02), GameRegistry (S01), GameInstanceDao (S01). WebView lifecycle is now owned by SessionController, not WebViewHost composable internals.

## Verification

- SessionController logs all state transitions with gameId + from/to state. BridgeValidator logs rejected messages with reason. No new observability surfaces beyond logging.

- [x] **T01**: SessionController Core _(2h)_
  Create the SessionController lifecycle-aware component that owns all session state transitions via the nine-state sealed model. This is the highest-risk first proof — if transitions are wrong, S04 resilience inherits bugs.

  **Why:** R009 requires SessionController as sole owner of the nine-state lifecycle. PlaySurface currently drives state via local `remember` — S03 replaces this with SessionController. The controller must expose StateFlow state, validate every transition through canTransition(), manage WebView lifecycle via profile binding, own the navigation epoch counter, and serialize conflicting operations.

  **Do:** Create `app/src/main/java/com/example/hub/session/SessionController.kt`. The class implements `LifecycleEventObserver` (not ViewModel — per D001/MEM001 spec prohibition on Activity-bound WebView in long-lived ViewModel). It holds:
  - `MutableStateFlow<SessionState>` initialized to `Closed`
  - `MutableStateFlow<String?>` for activeGameId
  - `MutableStateFlow<String?>` for activeProfileName
  - `MutableStateFlow<Int>` for navigationEpoch (starts at 0, increments on each open)
  - `GameRegistry` and `GameInstanceDao` dependencies
  - A coroutine scope for lifecycle-attached work
  - A mutex/serialized dispatch for conflicting operations (open while closing, etc.)

  Public API:
  - `suspend fun open(gameId: String)` — transitions Closed→Opening, resolves game from registry, creates/bind profile, transitions to Playing (or RecoveryRequired on failure)
  - `suspend fun close()` — transitions Playing→Closing→Closed, destroys WebView via callback
  - `fun requestCapture()` — transitions Playing→Capturing
  - `fun requestBackground()` — transitions Playing→Background
  - `fun requestForeground()` — transitions Background→Playing (or Capturing→Playing)
  - `fun requestRestore()` — transitions to Restoring
  - `fun requestDegraded()` — transitions Playing→Degraded
  - `fun requestRecovery()` — transitions Degraded→RecoveryRequired
  - `fun requestClosing()` — transitions any active state→Closing

  All transitions go through `canTransition()` validation. Illegal transitions log a warning and remain in current state.

  **Done when:** SessionController exposes StateFlow state, validates all transitions, owns game/instance identity, serializes conflicting ops. Unit tests cover valid transitions, illegal transitions, and identity tracking.

- [x] **T02**: Bridge Validation _(1.5h)_
  Create BridgeValidator (pure Kotlin, no Android deps) and BridgeHost (Android-side WebMessageListener wrapper) for origin-restricted message validation with epoch tracking and request correlation.

  **Why:** R011 requires bridge validation: origin restriction, current session/game check, navigation epoch check, request/result relationship validation, malformed messages fail closed. Late callbacks from old WebView/renderer/game/epoch must not mutate current session. The spec (D005) mandates origin-restricted WebMessageListener with navigation epoch tracking.

  **Do:** Create two files:
  1. `app/src/main/java/com/example/hub/bridge/BridgeValidator.kt` — pure Kotlin class with no Android dependencies. Exposes:
     - `validateMessage(sourceOrigin, approvedOrigins, currentEpoch, messageEpoch, outstandingRequests, messageId, payloadSize): ValidationResult`
     - Sealed class `ValidationResult` with `Valid` and `Invalid(Reason)` where Reason is ORIGIN_MISMATCH, EPOCH_STALE, REQUEST_UNCORRELATED, PAYLOAD_TOO_LARGE, SCHEMA_UNSUPPORTED
     - Pure validation logic testable on JVM without Robolectric

  2. `app/src/main/java/com/example/hub/bridge/BridgeHost.kt` — Android-side wrapper around `WebView.addWebMessageListener()`. Holds approved origins per game, tracks navigation epoch, maintains outstanding request set. Forwards validated messages to a callback. Rejects invalid messages silently with log.

  **Pattern:** The validation core is pure Kotlin. Tests run on JVM. BridgeHost is a thin Android wrapper that feeds messages through BridgeValidator.

  **Done when:** BridgeValidator rejects all five failure modes deterministically. BridgeHost compiles and wires to SessionController's epoch state. Unit tests cover all failure modes.

  **Why:** R010 requires moving WebView/profile/navigation ownership into SessionController: create/bind/navigate in defined order, each session has intended game profile, explicit WebView destruction, closing/switching invalidates old session, navigation epochs distinguish current from stale callbacks, recomposition irrelevant to WebView ownership. Currently WebViewHost does profile binding internally — this must be elevated to SessionController.
