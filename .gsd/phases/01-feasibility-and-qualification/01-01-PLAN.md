# S01: WebView Profile Capability Spike

**Milestone:** M001
**Slice:** S01

**Goal:** Deliver a minimal Android app that detects support for MULTI_PROFILE, DOCUMENT_START_SCRIPT, and WEB_MESSAGE_LISTENER on the target Pixel Fold, creates and inspects named WebView profiles to prove basic isolation, and reports all results in a native capability screen. Produces a capability report JSON file and UI display.
**Demo:** A minimal app that detects MULTI_PROFILE, DOCUMENT_START_SCRIPT, and WEB_MESSAGE_LISTENER feature support on the real Pixel Fold and reports results in a capability screen.

## Must-Haves

- WebViewFeature.isFeatureSupported() returns detectable results for all three features on the real Pixel Fold
- Capability screen displays WebView package/version and each feature support boolean
- Profile isolation test creates two named profiles at the same origin and proves localStorage keys do not leak between them
- Capability report JSON is written to app-private storage (filesDir/capability_report.json)
- The app compiles with minSdk 30, targetSdk 35, androidx.webkit:webkit:1.14.0
- If any required feature is missing, the UI shows remediation guidance

## Proof Level

- This slice proves: device-verified

## Integration Closure

S01 feeds S02 by confirming which WebView features are available; S02 depends on S01 passing to proceed with bootstrap ordering

- [x] **T03**: Implement the profile isolation test _(40m)_
  **Why:** S01 must prove that two WebView profiles at the same origin remain isolated. This is the only way to retire the "WebView feature availability on target device" risk for the MULTI_PROFILE feature. The test creates two named profiles, writes a localStorage key in one, and verifies it is invisible in the other.

  **Do:** Create `app/src/main/java/com/example/hub/diagnostics/ProfileIsolationTest.kt`. The test class exposes a `suspend fun test(profileStore: ProfileStore): TestResult` method. The test flow: (1) create profile "s01-test-a" and "s01-test-b" via `ProfileStore.getOrCreateProfile()`, (2) navigate each profile's WebView to a neutral about:blank or data: URL, (3) inject a JavaScript statement to write `localStorage.setItem('s01-test-key', 'profile-a-value')` in profile A, (4) query `localStorage.getItem('s01-test-key')` in profile B, (5) verify the result is null, (6) clean up both test profiles via `profileStore.deleteProfile()`, (7) return `TestResult(passed = true, message = "...")` on success or `TestResult(passed = false, message = "...")` on failure. Use `WebViewCompat.setProfile()` to bind profiles before any script execution. Wrap the whole operation in a try/catch; on exception return `TestResult(passed = false, message = exception.message)`.

  **Done when:** `ProfileIsolationTest.test()` returns `TestResult(passed = true)` on the real Pixel Fold. Test profiles are cleaned up after the test. If the test fails, profiles are retained for debugging (per D013).
  - Files: `app/src/main/java/com/example/hub/diagnostics/ProfileIsolationTest.kt`
